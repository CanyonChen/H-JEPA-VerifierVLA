        为什么下一步仍然输入 s₀？
        

          
公开代码允许两种输入：若收到当前状态 [B, dₛ]，就复制成 [B, M, dₛ]；若调用者已经提供逐子块的状态序列，就直接使用那份序列。因此，图中重复红块只对应第一种调用方式。

          
s₀ 可以作为整段预测的起点条件，动作历史和预测 latent 提供后续变化的信息。重复 s₀ 本身没有增加新的状态信息，也不会生成未来真实状态。这里要求训练与推理对状态 token 的含义保持一致；论文没有报告重复初始状态的专门消融，实际训练约定尚不能从公开代码确定。

Q 和 K 是怎样从 token 得到的？
            
先对每个输入 token 做 LayerNorm，再用共享的线性层投影为 Q、K、V。任务 query 是一枚输入 token；它也产生自己的 Q、K 和 V。名为“query”不意味着它只有 Q。
本数值实验使用固定的教学输入和三组 4 × 4 权重矩阵，确实计算 LayerNorm、线性投影、点积、掩码、softmax 和 V 加权和。为聚焦这些步骤，数值实验省略 RoPE、残差与 FFN；它不是完整 predictor 的运行结果。

06 · 从最后一层读取不同位置视觉 tokens → latent；任务 token → Δp̂

        

        

        
$$A=\operatorname{softmax}_{\text{keys}}\!\left(\frac{QK^\top}{\sqrt{d_h}}+\mathcal M\right),\qquad Y=AV$$

        
每个读取者有一整行权重，沿 key 维度归一化。允许读取的位置取掩码值 0，禁止的位置取 −∞。源码实际传入布尔掩码；这个加法公式是等价写法。RoPE 作用在 Q、K 的位置分量上，不改变形状。不同候选位于 B 维，互相不做注意力。

      

      

        任务 token 如何最终变成一个进度数？
        

          
当前任务 token 的 Q 对允许读取的 K 打分，然后把对应 V 加权汇总。这一步得到的是“该任务从当前动态上下文中读取到的信息”。各个注意力头读取不同特征方向；拼接各头、经过输出投影与残差后，再由逐 token 的 FFN 处理。重复多层后，任务位置的特征已融合动作、状态和视觉动态。

          
最后，value_tok = h[:, :, cond_tokens + HW, :] 取出任务位置，value_mlp(value_tok) 将 1024 维压成 1 维进度增量。名字虽然有 MLP，当前实现实际是一层 Linear。另一条输出从视觉位置取出特征，经 LayerNorm 和线性层映射回 dᵥ。两路头在同一次 forward 中读出；进度头的直接输入是任务 token 特征。

          
掩码阻断的是任务 token 流向动态 tokens 的前向信息路径，不会把共享 Transformer 的参数分成两套。视觉预测仍然会受动作影响；“任务无关”不等于“动作无关”。

论文：VeriVLA: Adaptive Test-Time Verification for Flow-Based VLAs with Latent World Models。作者：Xueli Sun、Yuxiang Lu、Yantong Liu、Xianzhe Fan、Xi Chen、Zhe Liu、Hengshuang Zhao，香港大学。原文 · 官方代码。

        
01 · 验证器解决“哪个候选更好”

        
流匹配 VLA 使用不同噪声可以生成不同的动作块。动作一旦执行就会改变物理世界，因此作者让策略先产生候选，再用一个独立验证器判断候选的效果。验证器不直接生成机器人动作，也不在这次推理中更新 VLA 的参数。双轴触发器先用少量动作样本检测值得花额外计算的时刻，再把候选扩展到完整预算。本文交互页面聚焦触发之后的验证阶段，展示三条候选是为了便于比较，不改变论文使用 K = 10 的设定。

        
02 · JEPA 规定预测目标，Transformer 实现预测

        
“action-conditioned autoregressive predictor”原论文 §3.4，Architecture：动作条件化的自回归预测器。

        
视觉编码器把图像变成一组 latent tokens。预测器用机器人状态和动作预测未来的同类特征。JEPA 的关键在于直接对齐表征：真实未来图像由编码器产生监督目标，模型学习使预测特征接近目标。它不需要为每条候选生成清晰的未来视频。当前源码通过多层 Transformer 完成这项预测，因此“采用 JEPA”与“主干是 Transformer”描述的是两个层次。

        
$$\mathcal L_{\mathrm{vis}}=\sum_{m=1}^{M}\left\|\hat z_{t+mH/M}-z_{t+mH/M}\right\|_1$$

        
这里 H 是动作块长度，M 是子块数；z 是真实未来观察的编码结果，带帽的 z 是预测结果。这个损失要求世界模型学习动作带来的变化。论文采用冻结的预训练视觉编码器，预测器具有机器人数据上的预训练基础，再针对验证任务训练。公开网络类本身不会自动加载这些预训练权重。

        
03 · 任务查询让同一变化获得不同评价

        
“task-specific learnable query token”原论文 §3.4，Architecture：每个任务对应一个可学习查询 token。

        
抬起电脑屏幕是否有利，取决于任务是打开还是合上。源码用 task_id 从 embedding 表里取出一枚向量，而不是在此处用语言模型解释任意新指令。这枚向量经自注意力更新后，读取到了与该任务有关的动作和场景信息。它是整个序列中的一个位置，和其他位置一样会生成 Q、K、V；任务专用性来自 embedding，读取范围则由注意力掩码规定。

        
掩码同时限制时间和任务信息。一个子块可以读取自己与过去子块的动态 tokens，不能读取未来。动态 tokens 不能读取任务 token，任务 token 可以读取自己的任务信息和合法的动态上下文，但不能读其他子块的任务 token。页面的斜纹格对应权重被严格置零的位置；解除任务隔离是人为设置的反事实，用于理解信息泄漏，不代表论文方法。

        
04 · 把每一步的进度相加，再比较候选

        
“largest cumulative predicted progress”原论文 §3.4，Inference：执行累计预测进度最大的动作块。

        
每个候选内部有 M 个相继的子块。第一个子块使用真实当前图像的 latent，之后使用前面预测的 latent，同时保留已有历史。候选之间可以放在 batch 维并行；同一候选的未来预测依次展开。进度头从每个子块的任务位置输出一个标量，这个标量对应进度变化，不是成功概率，也不是这里进行强化学习所用的 Critic 值函数。

        
$$S_i=\sum_{m=1}^{M}\Delta\hat p_m^{(i)},\qquad i^\star=\arg\max_i S_i$$

        
i 标记不同候选，m 标记同一候选的子块。一次局部倒退可以产生负的进度增量，但选择依据是整个候选的累计分数。训练时，作者将 Huber 进度回归、候选间排序与视觉预测结合；推理时仅做前向预测和排序。页面的打开/合上电脑演示使用可解释的角度分数，用来呈现这一逻辑，不是网络产生的预测。

真实任务的 65.5% 是按任务阶段累加的完成得分，不等于完整成功率。RoboTwin 表中的数字使用始终开启验证；自适应触发的计算与成功率权衡见原文 Fig. 6。因此，不能把所有指标直接横向比较，也不能将所有提升归因于触发器。更直接支持世界建模作用的是 Table 4：去掉视觉预测目标后，完成得分从 65.5% 降到 55.2%，说明共同学习动态对这组实验中的进度判断有帮助。

        
论文报告额外采样和验证共 326 ms，包含额外采样 80 ms 与验证器 246 ms。加上基础策略 82 ms 和触发器 14 ms，触发时总延迟是 422 ms。这些是论文配置下的测量，不是本网页运行的速度。

        
两个已知局限，以及一处尚未公开的约定

        
作者指出：验证器只能在策略给出的候选中选择，候选质量与多样性限制了改善空间；冻结视觉编码器也可能忽略接触、细小物体位姿变化等对操作进度重要的细节。理解这些边界很重要：评分准确并不能保证候选池里一定有可成功执行的动作。

        
代码阅读的边界：本页核对的是官方仓库 f95ab14（2026-10-16 提交），截至 2026-10-30 公开了模型结构与评分接口，训练、仿真和实机集成仍列在 TODO。网络构造默认值不等于所有实验的实际配置。本页采用 256 × 256、dᵥ = 768、D = 1024 的演示组合来讲张量，不能作为已发布检查点的配置说明。

        
尤其是红色机器人状态：重复 s₀ 是输入只有二维当前状态时的源码分支。模型并没有另一个状态头输出未来关节状态。把 s₀ 当作固定起点条件是可理解的解释，但是否与实际训练一致、重复输入是否有收益，都需要完整训练数据与集成代码才能核实。本页明确保留了这一未决点。
