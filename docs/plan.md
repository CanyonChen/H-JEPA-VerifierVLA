# 长程动作验证实验计划

更新日期为 2026-11-13。

研究方案已确认，P0 已完成 π₀.₅-LIBERO-Long 的单候选闭环与 500 回合评测，服务器回传 459 次成功、41 次超时，成功率 91.8%。P0 的同状态分支恢复验证、VeriVLA 资源核实与 P1–P5 留待后续推进。[baseline 记录](i_baseline.md)

当前评测主线为 LIBERO-Long 与 **LiLo-VLA Ultra-Long**。按用户于 2026-11-13 的要求，B4 从补齐 Spatial、Object、Goal 改为 Ultra-Long 的 9 个配置，先运行 π₀.₅ baseline，再以相同协议评测 π₀.₅＋原版 VeriVLA。B4 复用 B3 的模型与仿真环境，仅 GPU 1、最多两组并行。九回合 v2 smoke 为 0/9、AP 1.11%；独立三回合现场诊断为 0/3、AP 0，均无基础设施异常。行为诊断已收束，保留 v2 评分；核对一处回传计数不一致后推进首轮 90 回合，当前尚未运行。版本、项目适配协议及运行命令见 [B4 运行说明](lilo_baseline.md)。

可用资源：八卡 A100/H100 服务器、MuJoCo、松灵 Piper 等机器人。  
实施顺序：先在仿真中验证多个任务阶段之间的取舍，再进行真机验证。

**研究目标。** 先验证 π₀.₅＋原版 VeriVLA 在长程任务上的表现，再研究候选 action chunk 评分如何考虑当前 chunk 之后的任务完成能力。先验证长期评分的必要性，再验证 H-JEPA 式多时间尺度预测表示的独立作用。

**研究假设与评价目标。** 当前计划检验以下两个命题，不预设原方法的长程失败已经得到证明。

| 编号 | 假设 | 需要的证据 |
| --- | --- | --- |
| H1 | 在固定候选集合中，单个 chunk 的进度排序会在部分长程任务状态上偏离最终成功率排序 | 同一状态分支执行候选后，真实终点进度较高的候选，后续成功概率反而更低 |
| H2 | 在相同长期监督、数据及计算预算下，多时间尺度预测表示能比单层表示更准确地评价长期后果 | 层级版本在候选排序与完整任务成功率上稳定超过单层长期价值基线 |

VeriVLA 的子块进度标签满足：

```text
S(A) = Σ_m Δp_m = p(t+H) − p(t)
```

同一状态下，最大化该分数相当于最大化当前 chunk 终点的进度。五个子块仍只覆盖一个 chunk。预测值不一定严格相消，但监督目标的评价终点仍是 t+H。

第一轮长期目标定义为：

```text
Qπ(h_t, A, g, B)
  = P(先执行候选 A，再使用固定后续策略 π，
      在剩余预算 B 内完成任务 g | 当前信息 h_t)
```

其中，h_t 包含模型实际可用的观测、机器人状态及必要历史；A 是候选动作块；g 是任务；B 是剩余时间或步数。第一轮固定后续策略为基础 VLA，标签表示该策略下的后续成功概率。若实际执行的是动作块前缀，需要分别记录生成长度和实际执行长度，并按真实执行与重规划协议定义目标。

当前先推进 B4 的 Ultra-Long baseline 与原版 VeriVLA 长程对照。P1 的 1500 条分支续跑用于机制诊断，不作为这轮端到端对照的前置条件。P1 也可以在完整 VeriVLA 训练完成前利用真实候选终点观测检验进度目标；这种结论针对评分目标，不能替代原 VeriVLA 实际预测与选择的测量。

**P1：同状态分支实验协议。** 标准任务中的普通决策状态和阶段转换状态均应保留。专门挑出的冲突案例单独报告，不能替代标准任务总体结果。

1. 从实际 rollout 保存完整环境状态、任务逻辑状态、计时信息、策略历史和随机状态。
2. 在每个保存状态只生成一次 K=10 个候选；所有待比较评分方法使用相同候选集合。
3. 每次恢复相同状态，执行一个候选，记录动作执行过程及终点观测。
4. 在真实终点观测上计算 Robometer 进度差，并记录可用的环境阶段信息。
5. 使用相同后续策略、剩余预算和成组随机种子，续跑至任务终止或预算耗尽。
6. 记录最终成功、完成步数、失败位置、阶段完成或破坏，并比较候选排序。

| 项目 | 首轮安排 |
| --- | --- |
| 任务 | 从 2–3 个任务开始，先检查是否存在有意义的阶段取舍与候选差异 |
| 分叉状态 | 跨上述任务总计 50 个 |
| 每个状态的候选数 | 10 个 |
| 每个候选的续跑次数 | 3 次 |
| 先导续接轨迹数 | 50 × 10 × 3 = 1500 条 |
| 用途 | 筛查机制和估计数据需求；冲突状态追加重复，正式统计规模依据不确定性调整 |

上述数量是先导建议，不是已执行结果，也不是充分的统计门槛。

分支数据应保留 episode_id、分叉状态标识、任务、观测与本体状态、候选动作、实际执行长度、终点观测、进度标签、后续策略版本、剩余预算、续跑种子、终局结果。按完整轨迹或场景划分训练、验证和测试，同一分叉状态的所有候选与续跑结果保持在同一集合。环境阶段信息用于标签或诊断；若作为模型输入，需单列为使用额外状态信息的对照。

**候选评分诊断。** 同时比较以下四类信号，区分目标不匹配、预测误差和候选能力不足。

| 信号 | 回答的问题 |
| --- | --- |
| VeriVLA 预测的累计 Δp | 当前评分器实际会选哪个候选？ |
| 真实终点观测上的 Robometer Δp | 去掉潜在状态预测误差后，进度目标是否仍排错？ |
| 可用的环境阶段进度 | Robometer 的标注误差是否是主要原因？该信号本身也不等于最终成功率 |
| 分支续跑估计的最终成功率 | 在固定候选与后续策略下，长期选择有多大改进空间？ |

主要诊断指标为排序冲突、选择损失和候选集合的最佳长期表现：

```text
选择损失 = max_i Qπ(A_i) − Qπ(方法选中的候选)
```

分支成功率是有限样本估计，需要报告不确定性。用于挑选经验最佳候选的续跑种子与用于评价其效果的种子分开，降低选择偏差。

**P2–P3：模型实现路线。** 优先保持基础 VLA 和视觉编码器冻结，先建立单层长期基线，再增加两层预测表示。

```text
观测 / 本体状态 / 任务
        ↓
冻结的基础 VLA → K 个候选动作块
        ↓
VeriVLA 单 chunk 潜在状态预测
        ├─ 低层轨迹、动作与末端特征 ───────────┐
        └─ 高层编码器 → 高层状态表示 ─────────┤
                                             ↓
                                  长期成功率评分 → 选择候选
```

| 组件 | 第一版安排 | 训练信息 |
| --- | --- | --- |
| 基础 VLA | 固定候选生成能力 | 所有评分方法共享同一基础策略 |
| 视觉编码器与原预测器 | 在短期评分基线建立后，先冻结，隔离评分模块的贡献 | 保留原模型的预处理、视角和动作约定 |
| 单层长期评分头 | 使用候选动作及其预测轨迹、末端表示估计后续成功率 | 候选实际执行后，固定策略续跑的结果 |
| 高层编码器、动作聚合器与预测器 | 在 VeriVLA latent 上重新训练，先使用两层 | 真实连续轨迹中较长跨度的动作条件预测，例如 2H、4H；具体跨度待验证 |
| 层级长期评分头 | 联合低层细节与高层表示，预测与单层基线相同的长期目标 | 与单层版本相同的未来结果标签 |
| 原短期 Δp 头 | 保留为基线、辅助监督或诊断 | 原进度标签 |

高层长跨度预测第一版主要用于训练；推理仍可保留单 chunk rollout。将 t+H 的表示投影到高层，时间点仍是 t+H，长期信息来自后续结果监督。层级版本需与容量匹配的单层模型比较，不能将更大的模型或更多训练数据带来的收益归因于层级。

H-JEPA 上层权重不能直接接到 VeriVLA 上：两者的底层潜空间和模型接口不同。冻结底层的第一版属于“H-JEPA 启发的层级预测表示”，与原论文全层端到端训练区分。

训练评分头时包含预测器生成的 latent，避免只在真实观测编码上训练、却在想象状态上排序。保留真实末端表示输入的诊断版本，量化预测误差对长期判断的影响。

**多层级监督的后续选项。** 第一版以长期成功率作为选择依据。若阶段条件能够明确标注，再研究中期可达性；以下监督层次由目标定义，不能直接对应 H-JEPA 网络层号。

| 目标 | 含义 | 使用条件 |
| --- | --- | --- |
| 短期 Δp | 当前 chunk 推进了多少进度 | 原有监督 |
| 中期可达性 | 给定时间内能否满足下一阶段条件，并保留必要前提 | 需要明确阶段定义与标签 |
| 长期价值 | 剩余预算内能否完成整项任务 | 固定后续策略与终局结果标签 |

中期标签需区分“曾经完成”和“当前仍满足”。第一版不直接把不同含义的分数相加；如后续测试混合评分，将其作为独立经验基线调参和比较。

显式预测多个未来 chunk 留到后续：超过当前候选范围时，必须定义后续动作来源。基础 VLA 通常不能直接把想象 latent 当图像输入，因此需要额外的潜在策略、动作先验或规划器。

**任务与指标。** 标准任务与机制诊断分别报告。

| 类型 | 安排 | 用途 |
| --- | --- | --- |
| 已完成的标准任务 | LIBERO-Long，官方目录 `libero_10`，10 个任务、500 回合 | 保留 π₀.₅ 长程基线，并用于原版 VeriVLA 对照 |
| B4 超长程 benchmark | LiLo-VLA `ultra_long_all`，3 个场景 × 3 种技能顺序；每任务含 9、10 或 16 个技能，首轮 90 回合／方法 | 测量超长技能链与顺序变化下的 SR/AP；与 LIBERO-Long 分开报告 |

| 机制诊断：暂时调整 | 需要先移动障碍或撤回，再继续完成任务 | 检验短期进度与后续可达性的冲突 |
| 机制诊断：操作姿态 | 当前抓持方式影响后续插入、旋转或交接 | 检验跨阶段依赖 |
| 真机任务 | 将仿真中确认有效的取舍场景适配到 Piper | 检验机制在真实操作中的保持情况 |

任务名称含 Long 不代表必然存在排序冲突。首先检查任务中是否有目标取舍，以及基础 VLA 是否能生成不同长期后果的候选。

| 指标 | 作用 |
| --- | --- |
| 完整任务成功率 | 正式主指标 |
| Ultra-Long 平均进度 AP | 按指定顺序完成的技能数／总技能数，再对回合求均值；与 SR 一起报告 |
| 候选排序冲突与选择损失 | 检验评分机制 |
| 阶段完成、破坏及失败位置 | 解释长程结果；与完整成功率区分 |
| 完成步数 | 检查任务效率及预算影响 |
| 每次决策延迟、验证调用频率、参数量 | 比较收益与计算成本 |

正式关键对照采用多个训练种子、配对初始状态与置信区间。进入完整闭环后，新选择器会改变后续策略与访问状态分布，需要补充新策略轨迹，检查最初固定策略标签的适用性。

**阶段判断与转向标准。**

| 观察结果 | 解释 | 下一步 |
| --- | --- | --- |
| 预测 Δp 排错，真实终点 Δp 排得好 | 主要问题可能是世界模型或进度估计误差 | 优先改进预测与估计，再评价长期目标 |
| 真实终点 Δp 也排错，长期结果能区分候选 | 支持 H1 | 推进单层长期评分 |
| 候选集合中的最佳候选也没有改善空间 | 选择器受候选能力限制 | 优先检查候选生成 |
| 单层长期有效，层级无额外收益 | 长期监督有效，H2 尚未成立 | 保留有效长期方法，调整或停止层级路线 |
| 层级在匹配条件下持续超过单层 | 支持 H2 | 扩展任务并进入完整系统评估 |
| 离线评分有效，原触发器下无收益 | 可能缺少评分调用机会 | 分开分析触发位置和评分能力 |
| 只有更大模型或更多计算时层级才更好 | 层级贡献与容量或计算混杂 | 完成匹配比较再归因 |
